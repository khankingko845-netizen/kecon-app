# T07 — First-party measurement and AI cost ledger

## Scope and definitions
- No third-party analytics SDK, advertising ID, anonymous visitor cookie, device fingerprint, prompt, child/family name, email, audio, voice/story ID, URL of provider request, API key or provider error text in either measurement table.
- `user_id` is the existing account UUID and is personal/pseudonymous data: temporary tenant bridge until T08. Do not call it a household or anonymous statistic. Raw events/ledger are inaccessible even to staff clients. Admins get bounded aggregate SQL, gated by `analytics.view` and active admin session/MFA.
- No historical backfill. `signup` is a new profile created after migration, not email-confirmed registration. Visitors/abandoned anonymous onboarding and confirmation conversion are not measured.
- `home_view`: signed-in account mounts Home. `first_listen`: StoryPlayer browser `playing` event; client-reported actual media playback, NOT player mount, TTS prefetch, audio generation, silent reading or voice audition. These events are not fraud-proof. DB supplies account/time and deduplicates lifetime milestones.
- Funnel uses accounts signed up within 7/14/30 UTC calendar days, requires home >= signup and listen >= home. Optional create milestone is a DB story insert, not proof that all pages/audio were successfully produced. Staff accounts are excluded from funnel. Existing accounts may emit milestones but do not appear in new-account cohort. `story_created` is optional: a family can listen to the library without generating a story.

## Ledger and billing
- Every actual outbound paid attempt reserves a row before provider HTTP. Ledger/rate DB unavailable -> fail closed; no untracked spend. Existing quota checks remain unchanged (T21 compensation/idempotent quota is separate).
- LLM adapters receive injected measured transport, including both from-drawing calls; images include geometry in pricing model key (`dall-e-3.standard.1024x1024`, `1792x1024`, `1024x1792`). TTS, voice clone, legacy generated ambient and the paid Anthropic connection probe are instrumented; catalog/models/account metadata, free CDN ambient downloads, consent flows and cache hits are not AI spend.
- Each key-pool HTTP retry has its own ID and shares request ID. Ledger failure is not a provider-key failure: no failover/key cooldown for a measurement outage. Provider/model are the actual selection; Fish always platform-funded even if an unused ElevenLabs BYO field is supplied.
- Status is provider HTTP attempt result, not successful end-to-end story persistence. Timeout/failure may still have provider-side charges; failed estimates stay NULL (never $0).
- Token usage is validated numeric; Gemini output includes separately reported thinking tokens. TTS input units count Unicode code points after stripping emotion tags. Missing/partial/invalid usage stays NULL. New model/unknown plan/clone charges stay NULL without an explicit rate. Both zero usage with known price and a configured zero unit rate may legitimately yield 0.
- No fabricated/stale seed prices: current public pages did not establish rates for every configured legacy/custom model. Authorized `settings.write` staff can enter their verified contract/provider rate + HTTPS source in Cài đặt. Rates are USD/1M input/output tokens or USD/image, TTS character, clone attempt or ambient second. Check rates on the account/contract that pays, including plan multipliers. Pool-wide rate is an estimate, not exact per-key invoice allocation.
- Snapshot rate+source+updated time before each call. Updating a rate never reprices history. Price mutation is audit-atomic. Pricing tables cannot be directly written by staff. Known platform estimates, unknown charges, BYO and pending completions are separate in daily aggregates. Regular-token estimates do not apply promotional/free credits or cache discounts. Reconcile against provider invoice; never treat estimated total as final bill.
- Finalization retries once. A failure leaves the persisted `pending` record visible for reconciliation and logs only its random attempt ID, not body/error/key. This does not retry the paid provider call.

## Privacy/retention and operations
- Account deletion cascades measurement events and sets ledger `user_id` NULL (retains accounting totals without account linkage). No raw-table export or family drilldown UI.
- Run an operator-controlled retention job: delete events older than 90 days; unlink ledger accounts after 90 days; retain unlinked cost rows 365 days. Service-only `prune_measurement()` implements this and runs daily through the deployed systemd timer (03:17 UTC + up to 10 min jitter; persistent catch-up). Admin summary also invokes it after permission checks. Check `systemctl list-timers kecon-measurement-retention.timer` and service journal; alerting is separate A-16. T27/full privacy deletion proof and household consent are separate.
- Pending ledger rows mean “completion unknown”, not “provider still running”. Investigate server health and provider invoices; no automatic re-spend/reprice.
- Rollout: backup DB, dry-run migration 027 in BEGIN/ROLLBACK, apply before starting new application release. Do not enable paid app code without service-role credentials. No default-provider/key/voice/MFA change.
- Rollback: revert application release first. Keep additive tables/history and do not drop cost records. Restore DB only with explicit operational approval; reverted app stops new measurement.
